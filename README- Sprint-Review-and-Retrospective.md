## Computer Science Program Essential Questions

### 1. How do I interpret user needs and implement them into a program? How does creating "user stories" help with this?
Interpreting user needs begins with bridging the gap between nontechnical stakeholder requirements and technical system design. This is achieved by active listening, gathering detailed functional requirements, and translating business goals into system use cases. Creating "user stories" is vital to this process because it frames software development around the end-user's perspective, typically following the format: "As a [user persona], I want [feature] so that [benefit]." By focusing directly on user value rather than abstract technical specifications, user stories prevent scope creep, clarify acceptance criteria, and ensure that every line of code written directly serves a functional purpose.

### 2. How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?
My approach to developing programs is pragmatic, iterative, and user-centered. I break complex engineering challenges into manageable components using pseudocode, flowcharts, and object-oriented design principles, followed by incremental coding and rigorous testing. In my future development work, I plan to actively incorporate key Agile processes—specifically iterative sprint planning, continuous integration, backlog grooming, and daily stand-ups. Implementing these practices ensures high adaptability to changing requirements, rapid feedback loops, and consistent software quality.

### 3. What does it mean to be a good team member in software development?
Being a good team member in software development extends far beyond writing clean, efficient code. It means fostering psychological safety, communicating transparently, and respecting diverse perspectives. A strong team member takes ownership of their deliverables, proactively surfaces blockers before they derail a sprint, participates actively in code reviews and retrospectives with empathy, and supports peers when technical roadblocks arise. Ultimately, successful software engineering is a collaborative team sport where shared accountability and mutual support drive project success.
